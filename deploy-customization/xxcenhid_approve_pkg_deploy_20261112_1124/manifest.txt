## how to deploy
1. On the SOURCE application tier, in a copy of this folder: ./download.sh <environment file> run
   then copy the downloaded files (the @@OK lines) back into this folder.
README.md has the full instructions, including rollback; in short:
2. Copy the folder (or Make Zip) to the TARGET application tier and run:
   ./deploy.sh -e <environment file> -v  validates the target only: changes nothing
   ./deploy.sh -e <environment file>     validates, then deploys (-l lists the steps,
                                         -s N resumes at step N)
   Validation report: logs/validation.txt. A broken rule or a change that could lose data
   aborts before anything is changed (exit 3); objects the target already has unchanged are
   skipped; FNDLOAD / WFLOAD objects are backed up into logs/backup/ before uploading.
   ./deploy.sh -e <environment file> -r  rolls back the steps deployed, last first; -R does it
                                         by itself when a step fails. Code objects, views, FNDLOAD /
                                         WFLOAD and server files are put back; tables, data, grants
                                         and XML Publisher files are listed in logs/rollback.txt with
                                         how to undo them by hand (to avoid losing data).
   For a full undo of table / data changes, take a guaranteed restore point before deploying (adop mode: adop phase=abort discards the cycle).
   Unattended (CI/CD): set APPS_PWD and, if asked for, SCHEMA_PWD_<SCHEMA>.
   Logs are written to logs/; deploy.sh stops at the first step with errors.
